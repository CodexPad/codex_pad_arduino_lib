◆ Connect() [2/2]

bool codex_pad::Client::Connect ( gamepad::input::Button buttons)
noexcept

扫描附近的 CodexPad 设备，并自动连接到一个按键状态与指定掩码匹配的设备。

此方法会主动扫描蓝牙设备。当发现一个或多个 CodexPad 设备，其当前按键状态与提供的 button_mask 完全匹配时，它将尝试建立连接。 如果附近有多个设备都符合按键掩码，则会选择信号最强（RSSI 值最大）的设备进行连接。

参数
[in]button_mask用于匹配目标设备按键状态的32位按钮掩码。 使用 ButtonMask() 函数来组合多个 Button 枚举值。
返回值
true连接成功（找到了符合按键掩码的设备并成功连接）。
false连接失败（未找到匹配设备或连接尝试失败）。
注解
这是一个阻塞式调用。它会持续扫描，直到找到匹配的设备、连接建立或达到内部超时时间。
警告
**请勿**在按钮掩码中包含 Button::kHome。按住 Home 键会触发设备重启，这将中断连接过程。 示例：
codex_pad::Client g_codex_pad_client;
g_codex_pad_client.Init();
// 持续尝试连接到 Start 和 Cross/A 按键被同时按下的设备。
while (!g_codex_pad_client.ScanAndConnect(gamepad::input::Button::kStart | gamepad::input::Button::kStart)) {
// 可选：在尝试之间添加短暂延时或其他操作。
delay(100);
}
// 循环退出，意味着连接成功。
Serial.println("CodexPad 连接成功！");

int32_t codex_pad::Client::local_tx_power ( ) const
inlinenoexcept

获取用户设定的本地 BLE 发射功率值。

该函数返回之前通过 set_local_tx_power() 保存的值（或其默认值）。 注意： 当动态发射功率调节处于开启状态（默认开启，参见 set_dynamic_tx_power_enabled） 时，实际发射功率由基于 RSSI 的滞环量化器自动控制。此时，该函数返回的值**不能代表当前实时 使用的发射功率**，它仅代表内部存储的手动设定值。

返回
存储的本地 BLE 发射功率设定值，单位 dBm。

int32_t codex_pad::Client::rssi ( ) const
noexcept

获取已连接 CodexPad 的 RSSI（接收信号强度指示）。

该函数从底层 NimBLE 客户端获取当前的接收信号强度指示（RSSI）值。 注意： 在低于 3.1.0 的 ESP32 Arduino Core 版本中，RSSI 读数存在严重漂移（不准确）。 不推荐在旧版本中依赖此返回值进行逻辑判断或界面显示。如需准确的 RSSI 测量， 请将 ESP32 Arduino Core 升级至 3.1.0 或更高版本。

返回
当前 RSSI 值，单位为 dBm。如果 BLE 客户端未初始化或未连接，则返回 0。

◆ set_dynamic_tx_power_enabled()

void codex_pad::Client::set_dynamic_tx_power_enabled ( bool enabled)
inlinenoexcept

使能或禁用以 RSSI 为基础的动态发射功率调节。

该功能**默认开启**，且**强烈建议保持开启**。启用后，客户端会在 Update() 中周期性读取对端设备的 RSSI，并通过滞环量化器（Hysteresis Quantizer）动态调整本地 BLE 发射功率：

  • 信号较好（RSSI 较高）时，降低发射功率以节省能耗并减少无线干扰；
  • 信号较差（RSSI 较低）时，提高发射功率以维持连接稳定性。 与手动功率的冲突： 当动态调节开启时，通过 set_local_tx_power() 设置的任何功率值都会被 **覆盖**，无法生效。如果需要使用固定的手动发射功率，必须先调用 set_dynamic_tx_power_enabled(false) 关闭此功能。
    注解
    在 ESP32 平台上，该功能依赖 。由于在 **3.1.0 之前**的 ESP32 Arduino Core 版本中 RSSI 读数存在严重漂移（不准确），实际调节逻辑仅在 ESP_ARDUINO_VERSION >= ESP_ARDUINO_VERSION_VAL(3, 1, 0) 时才会编译和执行。在更早的版本中，内部已通过预处理器宏禁用动态调节，此时 set_local_tx_power() 可以正常生效作为回退方案。
    参数
    enabledtrue 表示开启（推荐），false 表示关闭并切换为手动控制模式。

◆ set_local_tx_power()

void codex_pad::Client::set_local_tx_power ( int32_t tx_power)
inlinenoexcept

设置本地 BLE 发射功率（手动模式）。

该函数用于保存期望的发射功率值。但是，**如果动态发射功率调节处于开启状态**（默认开启， 参见 set_dynamic_tx_power_enabled），该值将被忽略，并在 Update() 中被动态调节逻辑覆盖。 如需使该手动设置持续生效，必须先调用 set_dynamic_tx_power_enabled(false) 关闭动态调节功能。 在低于 3.1.0 的 ESP32 Arduino Core 版本中，由于内部因 RSSI 漂移已禁用动态调节，此设置可正常生效。

参数
tx_power本地 BLE 发射功率，单位 dBm。
